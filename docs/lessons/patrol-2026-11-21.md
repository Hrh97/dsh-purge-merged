## 五、候选整合项（按优先级，供 YG 决策）

- **A（可选，低风险）— 重试建流失败降级 + `outcome:"error"`**（社区 1.7.19）：本地 `lib/refusal-retry.js` 已有 asyncIterator 包装，但未见"重试建流失败/中途断流 → 吐出上一轮已缓冲拒绝文本 + audit `outcome:error`"的明确 fail-open 分支。社区实测该场景在子代理会话里会导致整回合失败。建议核对本地重试循环：若 `streamFactory(current)[Symbol.asyncIterator]()` 在重试轮抛错未被捕获，按社区写法移进 try、降级放行上一轮缓冲。带 2 条回归（建流失败 / 中途断流）。
- **B（可选，低成本）— 真实拒绝语料回归集**：社区 `test/refusal-corpus.test.mjs`（49 正样本 + 12 负样本 + 3 已知误伤）比本地散在 `refusal-retry.test.mjs` 的零散断言更系统。本地可建一份 corpus 测试锁定"中文拒绝句式 0 漏检、技术文本 0 误伤"，防止后续改 detection 规则时回退。
- **C（观察，需权衡）— workspace baseline 三态策略**（CallMeGuLab）：`strict`（丢宿主 baseline）/ `fallback`（用户 inject 存在才丢）/ `always`（保留）。本地当前是"prompt-inject.md 含出厂标记即判出厂默认回写覆盖"的固定策略；三态化更灵活，但会改变注入优先级语义，需先确认本地 `request-shape.js` 的注入叠加顺序，属中风险改动。
- **D（观察，UI 层）— `/rewind` 当前轮回退**：按当前轮而非首条 user 消息回退、消息退回输入框、已完成任务退出会话。本地已有撤销机制（AGENTS.md 记 `/rewind` 由 dsh-purge 管理），需核对是否已经等价，避免重复。
- **E（不吸收，记录理由）**：`refusalSeed`（默认关、社区自承很少触发）、1.7.13/14 更新诊断与 UI、1.7.15 权限显式化（与本地默认全开相悖）、1.7.16 dsh-go/DSH NEXT 私有宿主分支。
