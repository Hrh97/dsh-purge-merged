## 二、rc.5 真缺口（5 处，全部已落地）

宿主从 0.2.2-rc.3 升到 **0.2.2-rc.5** 后，四处官方改动让本地代码静默失效，外加 CLI 宿主识别错。

### 缺口 1：`client.inject` 引用了 rc.5 已移除的包 ✅

- 宿主 `resources/app/dsh/node_modules/@deepseek-ai/` 实测：`dsh-client-runtime` **不存在**、`dsh-client-ui-slots` **不存在**。
- 缺失依赖会让 `dsh-client-modules` 抛 `client-modules: "<consumer>" not loaded because dependency "<id>" failed`（`lib/index.js:783 resolveMeta()` → `parseDshClient()` → `optionalStringArray(pkgName,"dsh.client.inject",…)`）。
- 官方 rc.5 自己的声明里 `slots` 服务已由 `dsh-client-ui-renderer` 提供。
- **修法**：`package.json` 的 `dsh.client.inject` 改为 `[connection, locale, ui-settings, ui-conversation]`。
  - 依据 **CallMeGuLab v2.0.2**（ZXEB v1.1.76 自己也还在引用已移除的 client-runtime/ui-slots，不能照抄）。
  - 保留 `ui-conversation` 是因为本地 `lib/core.js` 的 `conversation-client` 补丁键打它的 `lib/client.js`（#56/#77 依赖）。

### 缺口 2：redteam 调 `ctx.subagents.listChildren`，rc.5 只有 `listDescendants` ✅

- rc.5 `dsh-subagent` 的 SubagentRuntime 只暴露 `listDescendants(rootSessionId, signal)`（`dsh-subagent/lib/index.js:3156`；`src/index.ts:427`），模块内 `list-children.ts` 只导出内部函数，**运行时服务面没有 listChildren**。
- 本地调用点：`lib/redteam/tools.js:316,320`（`liveRunningChildren`）、`lib/redteam/ui.js:344`、`:934`。
- **修法**：三处都改成双兼容 —— 有 `listChildren` 用旧的、没有就用 `listDescendants`；rc.5 的 `listDescendants` 返回整棵子树，用 `depth === 1` 过滤出直接子；标签回退顺序 `label || name || id`。

### 缺口 3：`PERMANENT_CODES` 缺 rc.4/rc.5 新码 ✅

- 宿主 `dsh-llm/lib/index.js:134` 的 `LLM_FAILURE_CODES` 共 **53** 个；本地 `lib/continue-retry.js` 原来只有 **15** 个。
- 其中 `CONTENT_REFUSED`（`dsh-llm-deepseek/lib/index.js:1971` `throw new LlmError("DeepSeek refused to answer under its content safety review…", "CONTENT_REFUSED")`）此前会落 `MALFORMED_RESPONSE`，看起来像网络抖动 → continue-retry 每轮重试、白烧 token。
- **修法**：`PERMANENT_CODES` 扩到 **31** 个，新增 `CONTENT_REFUSED`、`ACCOUNT_SIGN_IN_REQUIRED`、`ACCOUNT_TOKEN_INVALID`、`CLIENT_UPGRADE_REQUIRED`、`MODEL_UNSUPPORTED`、`UNKNOWN_MODEL`、`UNSUPPORTED_CONTENT`、`UNSUPPORTED_OPTION`、`UNSUPPORTED_REASONING_EFFORT`、`INVALID_MODEL_CONTEXT`、`INVALID_MODEL_INFO`、`INVALID_MODEL_MAX_TOKENS`、`INVALID_MODEL_REASONING`、`NO_CREDENTIAL_STORE`、`INVALID_CONFIG`、`TOOL_ACTIVATION_FAILED`、`DSH_TOOL_FORMAT`。

### 缺口 4：CLI 宿主识别错（报旧 web 副本）✅

- 改前 `node bin/dsh-purge.js --status` 报 `D:\hrh\dsh\node_modules\@deepseek-ai`（host **0.2.1-rc.3**，一份旧 web 副本），实际在跑的是桌面版 **rc.5**。
- **修法**（比 qiuqianyi66 多一层）：
  - `lib/core.js` 新增 `looksLikeStaleBase(dir)`：`/_npx/`、`/npm-cache/`、`/_cacache/`、`/.pnpm/`、`_archived-`、`.trash`、`/backup/`。

  - 改后 `--status` 报 `D:\Program Files\DSH\resources\app\dsh\node_modules\@deepseek-ai`，host = **0.2.2-rc.5**。

### 缺口 5：`presets/redteam/agent.cordis.yml` 子代理 schema 未迁 rc.5 ✅

## 三、落地过程中又挖出来的两个洞（本轮新增）

### 洞 A：补丁门控按「当前进程」判区 → 11 条 desktop-only 补丁误报 na

- 缺口 4 修好后，CLI 正确指向桌面宿主了，但 `patchAppliesHere(patch, surface = detectSurface())` 判的仍是**当前进程**（CLI 在普通 node 下 = web）→ 11 条 desktop-only 补丁（#45/#46/#82/#83/#84/#92/#93/#100/#103/#108/#109）在状态页全判 `na`，看着像「桌面补丁一条都没打上」，其实它们都写在桌面壳 `main.js` 里。
- **修法**：新增 `surfaceForAiBase(aiBase)` —— 宿主路径落在桌面安装树内（`desktop.isInsideDesktopInstall`）→ `desktop`，否则沿用当前进程。门控点统一走它：
  - `patchStatus` / `applyPatches` / `groupPatchesForDisplay` / `gatherState` / `patchesTouching`+`backupNotNeeded`（`lib/core.js`）
  - `lib/anchor-doctor.js` 的 `diagnosePatches`（原来 `options.surface` 默认 undefined → 落回 detectSurface）
  - `targetFiles()` 里的 `officialShellMain()` 也要按宿主分区找文件，否则 `desktop-shell` 键恒空。
- **实测**：状态页 11 条 desktop-only 补丁从 10×`na` + 1×`drifted` 变成 10×`applied` + 1×`applied`。

### 洞 B：rc.5 前端产物是压缩单行，#56/#77 的锚点全失配

- rc.5 的 `dsh-client-ui-conversation/lib/client.js` 是压缩单行（687KB 单行）。#56 `REWIND_HIDE_CUT_ONLY` / #77 `REWIND_DROP_SENT_ON_APPEND` 的多行锚点全部匹配不到 → 功能随官方升级**静默失效**（回退后被撤掉的轮次还留在聊天里）。
- **修法**：吸收 ZXEB v1.1.76 的「0.2.2+ 压缩版」锚点：
  - #56：`pattern: "var ConversationNodeAssembler=class{"` → 注入 `isRewindMarker` + `rewindVisibleEntries` 两个单行函数；`pattern: "replaceWindow(entries,hasMore){this.contexts.clear();"` → `entries=rewindVisibleEntries(entries);`。
  - #77：`pattern: "append(record){const event=record.event;if(this.inputs.has(event.seq))return\`none\`;if(this.revised.size>0)this.revised.clear();this.inputs.set(event.seq,record);"` → 中间插 `isRewindMarker` 分支走 `replaceWindow`。
  - 注释用 `/* [dsh-purge] … */` 块注释（单行安全），正则锚点用 `typeof isRewindMarker==="function"` 守卫（防二次 apply 重复注入）。
- **验证**：离线脚本 `D:\tmp\verify-rc5-rewind.mjs` 对真实 rc.5 宿主文件跑 `applyReplacementsToText` → 两个补丁各自 `changed=true` / `hitMismatch=null`，产物 `node --check` 通过，串起来落地也通过。

### 洞 C（附带）：#103 的 welcome cookie 清扫，rc.5 官方自己实现了

- rc.5 桌面壳新增 `removeLegacyHostCookies(cookies, url)`（`main.js:15392`），在 `start()` 里 `authenticateWebHost` 之后调用，清掉 jar 里全部 `dsh-auth-*` —— 与我们 #103 做的**是同一件事**。
- 但官方把锚点那行改写成了 `welcomeBackend = connectDesktopWelcome(ready.url, cookie);`（cookie 变量形态），我们的 pattern 失配 → 状态页报 `drifted`（官方原文已改）。
- **修法**（沿用 #94/#95 的既有做法）：`markersAny: true` + `softSettle: true`，marker 追加 `removeLegacyHostCookies`。
