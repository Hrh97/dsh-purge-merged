## 四、新发现项目与可吸收判定

### 4.1 NANA7MI0/dsh-purge-go（手机端移植，更新最活跃）

- [仓库](https://github.com/NANA7MI0/dsh-purge-go) · 117 star · 11-24/25 连发 **0.7.1 / 0.7.2**。
- 0.7.1（`7d2c16a`）：命令行更新丢补丁、脏引擎提示失效、平板更新总失败。修法要点：
  - `prepareBackup` 挪进 `prerestore` 之前，`--no-topup` 可关；
  - 收尾六步抽成 `settle-steps.mjs` 公共模块；
  - 覆盖仓库改成「**先铺新的、再删多余的**」，SIGTERM/SIGKILL 打断都不留空仓库，先拷 `package.json` 与 `lib/` 保证能启动；
  - `curl` 换 Node 原生 `fetch` + 超时 + 版本守卫；失败原因不再误报网络。
- 0.7.2（`16b8055`）：慢网点更新会失败、分类规则正文改成密文。
- **判定**：DSH-GO 手机端（Flutter 壳 + proot），补丁载体与桌面完全不同，**功能不可直接移植**。但「**更新器鲁棒性**」三条思路对本地 `--self-update` / reapply 链有借鉴价值：① 覆盖式升级先铺后删（防中断留空目录）；② fetch 超时 + 版本守卫 + 失败原因分流（本地 github 间歇不可达，当前靠缓存兜底，可再加超时细分）；③ 收尾步骤抽公共函数避免多处漂移。列为**中优先级候选**。

### 4.2 yushang657/DSH-YS-pojia（新三层破甲项目）

- [仓库](https://github.com/yushang657/DSH-YS-pojia) · 20 star · v1.5.3（11-24 更新）· Apache-2.0。
- 三层结构：宿主补丁（96/70 文件）、消息层 `lib/message-purge.js`、提示词层 11 段。
- 与本地对照：

| 其机制 | 本地对应 | 判定 |

| 历史拒答擦除（改 `deriveMessages()` 返回值，把历史拒答标"作废"） | `request-shape.js` 已有 `stats.refusalsShadowed` 擦除 | **已覆盖** |
| assistant prefill（追加半句合规开头），声称只改返回值、不持久化 | 本地 1.0 时代实现过，2026-10-26 因引导串进 user 消息（"已开始输出："）**整段删除、不留开关**（request-shape.js:428-436） | **谨慎**：其实现声称走 native `source.kind=purge-prefill` assistant 消息 + 只改 `deriveMessages()` 返回值，理论上绕开本地踩的坑。需读其 `message-purge.js` 确认注入点后再决定，列为**观察项** |
| 自适应升级阶梯 S0–S6（按拒答类型选下一档） | `retry-ladder.js`（sanitize/decompose 阶梯）+ `refusal-retry.js` | **本地已有等价阶梯**，但其"按拒答类型分流"的判定维度更细，可作增强参考 |
