## 三、可吸取点逐条分析（按价值排序）

### ★★★ 1. assembleGuard 静默丢工具 —— 本地存在同款真 bug（ZXEB v1.1.75）

ZXEB 描述：rc.3 把工作目录改成独立服务，`{{cwd}}` 不再注册，`dsh-system-prompt` 对未注册变量**直接抛** `unknown prompt variable`。本地 `lib/identity.js:916` 的兜底恰好把异常吞成空装配：

```js
// lib/identity.js:916（现状）
return slot.lastGood || { sections: [], contexts: [], tools: [] };
```

后果与 ZXEB 实测一致：组装失败 → `tools: []` → 模型没有可调用 schema → 把工具调用写成正文（DSML），表象是"模型不会调工具"，真因是兜底吞了 schema。

- **本地已覆盖的部分**：`{{cwd}}` 变量问题本地用 `#204` 方案解决（`identity.js:228-245` 真实 cwd 字面量 + `withCwdVariable` 补进 `assembly.variables`），比 ZXEB 的 `working-directory-compat.js` 更早、更彻底，这一层不用搬。
- **本地未覆盖的部分**：组装彻底失败时返回空工具列表这个兜底行为。本地有 `slot.lastGood` 回退（比 ZXEB 原始版好），但首次就失败时仍落空工具。
- **ZXEB 修法**：兜底改为 `throw err`，让失败显式暴露，再配 `lib/native-tool-compat.js` 做 DSML 正文兜底（仅 provider=opencode-go + model=deepseek-v4.1-flash + 带工具时生效）。
- **建议**：`throw err` 会改变"任务到一半苏醒"那类场景的现有行为（本地注释明确是为避免 waterfall 崩掉才吞的），不能照搬。更稳的折中：空装配时保留上一次工具的 schema、或仅在 `tools` 为空且本轮应有工具时 throw。需要先补一条"组装失败不丢工具"的回归测试再动。
- **对位文件**：`lib/identity.js:900-920`、`test/identity.test.mjs`。

### ★★ 2. baseline_lost 假还原检测 —— 本地没有（qiuqianyi66 1.2.6）

qiuqianyi66 发现：`.dshpurge.bak` 只在缺失时创建，"先打补丁、后才有备份"的历史状态会把**已打态**存成基线，`revertAll` 把补丁文件覆盖回自己 → 0 差异、报成功、补丁全在。真机 54 个备份里 10 个中招。

- **本地现状**：`lib/core.js` 的 `revertAll` 遇到 `bak` 与本体同字节直接 `skipped`，没有"同字节 + 本体带补丁痕迹 = 基线丢失"的判定，用户点还原会以为退回原版。
- **可搬形态**（已在 qiuqianyi66 1.2.6 验证，5 条测试）：`detectBaselineLost()` —— 对每个载体，若 bak 与本体同字节且本体有补丁痕迹（marker 命中 + 原 pattern 不在），单列 `baseline_lost`、保留 bak 留证、不计入 reverted，`--revert` / 面板 / `--apply` 都告警；无补丁痕迹的同字节文件仍按 skipped 不误报。
- **价值**：这是"还原可信度"的基础设施，与宿主 rc.3 解包 asar 后基线容易写坏的现实强相关。对位 `lib/core.js` 的 `revertAll` / `revertAllHosts` / CLI `bin/dsh-purge.js` / `lib/index.js` 的 `/purge revert`。
- **建议**：优先级次于 #1，但实现边界清晰、可独立成补丁 + 测试，适合单独一轮吸收。
