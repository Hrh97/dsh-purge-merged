## 三、可吸收点逐条分析（按价值排序）

### ★★★ 1. content 形状统一为 block 数组 —— 本地存在同形缺口（devin667 rc2.13.1）

上游描述：`stripRefusalHistory` / `withNudge` 把内容写成字符串，宿主发请求前 `message.content.some(...)` 直接抛 `TypeError`，且畸形消息已进历史、之后每轮重炸。修法是一律输出 block 数组，并补 `normalizeContentShape` 的 import。

本地对位：`lib/refusal-retry.js:60-75` 的 `withNudge(options, nudge)`：

```js
const content = Array.isArray(first.content)
  ? first.content.map((block) => (block && block.type === "text" ? { ...block, text: `${block.text}\n\n${text}` } : block))
  : (typeof first.content === "string" ? `${first.content}\n\n${text}` : first.content);
return { ...options, messages: [{ ...first, content }, ...messages.slice(1)] };
```

- 当 `first.content` 是字符串时，本地把它拼成**更长的字符串**塞回 `messages[0].content` 并返回。若宿主侧对 system content 调 `.some(...)`（devin667 在 rc.3 实测），这里就是同源触发点。
- 本地作者刻意保留了字符串分支，说明某些 preset（minimal / ptc 类）下 system content 确实会是字符串——分支是活的，不是死代码。
- **建议改法**：字符串形态统一转成 `[{ type: "text", text: ... }]` 输出；保留「没有 system 消息就原样返回、不硬造一条」的既有约定。改动面只在 `withNudge` 一个函数，配套补一条「字符串 content 输入 → block 数组输出」测试。
- 注意：`lib/continue-retry.js` 若有同类 content 拼接也要一起扫（本轮未逐行核，落地前先 grep）。

### ★★ 2. 假成功审计标签 + drain 全文采样 —— 本地判定口径缺口（kingcharleslzy 1.7.20）

1.7.20 指出两种被误记为 `recovered` 的假成功：

| 标签 | 触发条件 | 是否重试 |
| --- | --- | --- |
| `partial_refused` | 全文出现拒绝句式且交付薄（<10 行代码 且 <5 条步骤） | 不重试 |
| `empty_after_retry` | 重试后文本 <200 字且交付薄 | 不重试（已重试过） |

实现要点：缓冲只有前 400 字，看不到放在后文的拒答 → 在 drain 阶段采样最多 8000 字，流结束后统一判定一次。

本地对位：`lib/refusal-retry.js:30` `DEFAULT_BUFFER_CHARS = 400`，`isTerminalChunk()` 只把 tool-call/finish/error 当放行信号，drain 之后没有全文复判；`onRetry` 回调（`lib/refusal-retry.js:197`）带 `action/attempt` 但没有交付厚度判定，`recovered` 语义缺失。

- 这是**审计口径**缺口，不改破甲行为本身：开着 refusalRetry 时，「先给背景再把请求推掉」和「重试后空转」在统计里都算成功，会让使用者误判插件在干活。
- **建议改法**（若吸收）：drain 阶段累积最多 8000 字做一次全文拒绝判定 + 交付厚度计数，`onRetry` 增 `outcome` 字段。优先级低于第 1 条，且要防止「全文整词表命中正常工作句」的误伤（本地 `REFUSAL_MARKERS_ZH_STEALTH` 是带宾语整词表，正好可用，不要放宽成锚句末正则）。

### ★ 3. baseline_lost 复发口子 —— 本地架构不同，部分不适用（qiuqianyi66 1.2.7）

1.2.7 修的是：宿主重启走「过期基线上刷新」自愈（`refreshStaleBaksForUpgrade`），旧判据「无 `dsh-purge` 字面量 + 与 bak 不同 → 官方新版，刷 bak 成正文」会把刚重建的基线又刷回已打态——只改文案、不写 marker 的补丁（本地 #1/#22/#33/#48 同类）反复复发。

本地 1.2.5 的 `detectBaselineLost()` 是**只读检测 + 提示重建**，没有 qiuqianyi66 那条自动刷新基线的自愈逻辑，所以「自愈把基线刷回去」这个具体复发路径在本地不存在。但判据思想值得记：**「marker 命中 + 原 pattern 已不命中」才是「已打态」的可靠判据**，字面量缺失不能当作官方新版的证据。本地今后若加自动基线刷新，必须按此判据。

### ★ 4. 图像类推脱规则（devin667 rc2.11）—— 待定，不急吸收

rc2.11 把 `REFUSAL_PATTERNS` 从 14 条扩到 24 条，新增 10 条针对图像任务的推脱话术（「这张我跳过」「属于对真人的性化处理，这条我不接」「我无法核实，不改变性质」等），并配图像专用重试帧（首句 `Call the image tool now`）。

本地 `lib/request-shape.js:99` 的 `REFUSAL_PATTERNS` 是通用文本 + stealth 词表，没有图像专用形态，也没有按 `content[].type === "image"` 切帧的逻辑。本地定位是通用破甲，图像类是否纳入属于产品取舍，不作为本轮建议。
